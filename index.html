核心转变

从“预先投喂”，到“按需发现”。

过去，系统用 RAG 或固定提示词预先挑选资料，再交给模型。现在，我们可以提供搜索、读取与执行等基础能力，让 Agent 根据当前问题自行决定：下一步该找什么、该读多深、何时停止。

短文

渐进式披露：Agent 不是记住一切，而是会找到恰好需要的东西

我们常把 AI 的能力理解为“知道得多”。但在真实工作里，更重要的能力往往是：面对一个具体问题，知道先查哪里，再根据新证据决定下一步。渐进式披露把这种能力变成系统设计原则。

它的起点很朴素：不要在任务开始时把整套文档、全部代码或整个知识库塞进上下文。先给 Agent 一个任务和少量可靠的入口，例如文件搜索、目录索引、技能说明或数据库查询规则。Agent 发现一个相关文件后，再读取其中指向的下一份材料。每一层信息都由上一层的证据触发。

这样做的收益不只是节省 token。它让推理过程更贴近人类研究：上下文更相关、信息来源更可追踪，也更容易适应不断变化的代码库和业务规则。Agent Skills 的价值正在于此：它们不是把所有能力做成更多工具，而是为已有的搜索与读取能力提供一条可探索的知识路径。

因此，设计 Agent 时要问的不是“还要不要再加一个工具”，而是“它能否在需要时，自己发现使用现有能力的方法”。当答案是肯定的，系统就能以更低的复杂度持续扩展。

迁移与创新

把“上下文阶梯”移到别的领域

共同原则：不预装所有规则，而是让当前信号引出下一层必要的证据和权限。

01

客服的“证据式升级”

先读订单与当前对话；只有出现退款、物流异常或争议信号时，才展开对应政策、仓储记录和人工升级路径。

结果：更少误引用政策，更快把复杂问题交给正确的人。

02

临床协作的“最小知情”

先用主诉、过敏史和关键指标生成下一步检查建议；确有必要时才请求专科病历或历史影像，并记录理由。

结果：兼顾隐私边界、审计要求与协作效率。

03

工业运维的“故障地图”

从实时告警开始，按组件依赖关系逐层展开传感器数据、变更记录、维修手册和备件库存，而不是扫描全部设备日志。

结果：把告警风暴转为可解释的排障路线。

设计检查

新增功能前，先检查这三个问题。

  1. Agent 是否已经拥有足够的基础动作，例如搜索、读取、查询或执行？
  2. 能否把新知识写成一份按需发现的说明，而不是新增一个专属工具？
  3. 每次展开是否由当前任务的证据触发，并且能留下可审计的轨迹？
